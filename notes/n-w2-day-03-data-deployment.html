오늘 수업 내용 정리

세션 1. 프로젝트와 지침

  • 프로젝트는 대화와 자료를 모아 두는 폴더입니다. 클로드는 새 대화를 열면 앞의 일을 모르고 시작하는데, 프로젝트에 배경과 지침을 넣어 두면 그 안의 모든 대화가 같은 규칙으로 시작합니다. 비유하면 매번 새 직원에게 업무 인수인계서를 다시 쓰는 대신, 책상 위에 인수인계서를 붙여 두는 것입니다.
  • 지침은 답을 보고 지켰는지 확인할 수 있게 써야 합니다. "친절하게"는 확인이 안 되고, "표로 먼저 보여 준다"는 확인이 됩니다. 그래서 지침마다 확인 방법을 옆에 적습니다.
  • 같은 질문을 프로젝트 안과 밖에서 던져 답을 비교할 수 있습니다. 밖에서도 PRD를 아는 것처럼 답하면 메모리가 켜져 있어서일 수 있으니, 비교할 때는 첫 메시지를 보내기 전에 메모리를 끕니다.
  • 지침은 잠금 장치가 아닙니다. 지침과 반대로 요청하면 지침보다 지금 한 요청을 먼저 따릅니다.

세션 2. 메모리와 예약 작업

  • 메모리는 대화가 바뀌어도 나에 대한 내용을 기억해 주는 기능입니다. 다만 날짜와 숫자를 정확히 기억한다고 믿으면 안 되고, 원본 자료에서 다시 확인해야 합니다. 프로젝트마다 메모리가 따로이고, 대화를 지워도 그 대화에서 생긴 메모리는 남습니다.
  • 예약 작업은 정해진 시간에 클로드가 알아서 일하게 하는 기능이고 유료 플랜에서 쓸 수 있습니다. 만들기 전에 네 가지를 정합니다. 무슨 일을 할지, 언제 할지, 결과를 어디서 볼지, 어떻게 멈출지입니다.
  • 주기는 매시간, 매일, 매주, 평일, 수동 중에서 고릅니다. 끝나는 날을 정하는 설정은 없어서 끝낼 날에 직접 멈추거나 지워야 합니다.
  • 명세서를 줄 때 "빠진 정보가 있으면 먼저 질문해"라는 한 줄을 넣으면 잘못된 예약을 막을 수 있습니다.

세션 3. 클로드 인 크롬과 맡길 일 고르기

  • 클로드 인 크롬은 클로드가 내 크롬 브라우저에서 웹사이트를 읽고, 클릭하고, 이동하게 해 주는 확장 프로그램입니다.
  • 권한 모드는 세 가지입니다. 동작마다 허락을 받는 모드, 안전 검사 후 진행하고 애매하면 묻는 모드, 검사 없이 진행하는 모드입니다. 마지막 모드는 완전히 믿는 일에만 씁니다.
  • 어떤 모드에서도 묻는 동작은 민감한 정보 입력, 파일 다운로드, 권한 부여, 설정 변경입니다. 결제, 계정 만들기, 카드와 신분증 정보 처리, 영구 삭제는 아예 하지 않습니다.
  • 맡길 일은 맡김, 멈춤, 안 맡김으로 나눕니다. 가장 먼저 묻는 질문은 "잘못되면 되돌릴 수 있나"입니다. 읽기만 하는 일은 맡기고, 제출이나 저장 앞에서는 멈추고 내가 확인하고, 보내면 되돌릴 수 없는 일은 맡기지 않습니다.

세션 4. 신청 데이터 정의

  • 신청 페이지에 저장 기능을 붙이기 전에 어떤 데이터가 들어오고, 남고, 지워지는지 표로 정합니다. 입력, 저장, 삭제 데이터와, 사용자가 아무것도 하기 전에 미리 있어야 하는 기본 데이터로 나눕니다.
  • 사전 신청에 필요 없는 개인정보(생년월일, 주소 등)는 받지 않습니다. 받는 것이 많을수록 동의 문구가 길어지고 지켜야 할 책임도 커집니다.
  • 이 표는 이후 데이터베이스 설계도가 됩니다.

세션 5. 아티팩트를 index.html로 내려받기

  • 배포 서비스는 대부분 폴더 안의 index.html을 첫 화면으로 보여 줍니다. 파일 이름이 다르면 주소에서 첫 화면이 안 보입니다.
  • 디자인과 동작이 한 파일 안에 모두 들어 있어야 어느 배포 서비스에서도 똑같이 보입니다. 내려받은 파일은 더블클릭해서 브라우저에서 열리는지 먼저 확인합니다.

세션 6. 배포 1, 넷리파이 드롭

  • 폴더를 끌어다 놓으면 인터넷 주소가 생기는 가장 단순한 배포입니다. 배포는 내 컴퓨터의 파일을 인터넷 주소로 열 수 있게 올리는 일이고, 비유하면 내 방 그림을 학교 복도 게시판에 붙이는 것입니다.
  • 고칠 때마다 폴더를 다시 끌어다 놓아야 합니다. 로그인하지 않고 올리면 주소에 임시 비밀번호가 걸립니다.

세션 7. 배포 2, 깃헙 저장소와 버셀

  • 깃헙 저장소를 버셀에 연결하면, 깃헙에서 파일을 고쳐 저장(커밋)할 때마다 사이트가 저절로 바뀝니다. 이렇게 올리면 자동 배포되는 흐름을 CD라고 합니다.
  • 원본(main)은 두고 다른 브랜치에서 고치면 실제 사이트는 그대로이고 미리보기 주소만 따로 생깁니다. 이것이 프리뷰 배포입니다.
  • 이전 배포로 되돌리는 것을 롤백이라고 하고, 롤백한 뒤에는 되돌리기를 취소해야 다음 커밋이 다시 자동 반영됩니다.
  • 배포 전에 코드를 자동으로 검사하는 CI는 오늘 쓰지 않았기 때문에, 오늘 만든 흐름은 CI/CD가 아니라 CD입니다.
  • 버셀 무료 계정은 조직이 가진 비공개 저장소를 배포할 수 없어서 개인 계정 저장소를 써야 합니다.
  • 두 배포 비교: 넷리파이 드롭은 내가 직접 끌어다 놓고 오늘 당장 보여 줄 시안에 맞고, 버셀은 커밋만 하면 자동으로 올라가서 계속 고치는 서비스에 맞습니다.

세션 8. 브라우저 저장과 한계

  • 웹에는 세 등장인물이 있습니다. 화면을 보여 주는 브라우저(내 기기), 요청을 받아 처리하는 서버(항상 켜져 있는 컴퓨터), 데이터를 모아 두는 데이터베이스(공용 서랍)입니다.
  • 브라우저 저장은 서버 없이 지금 쓰는 브라우저 안에만 저장합니다. 새로고침해도 남지만, 시크릿 창, 다른 브라우저, 다른 기기, 주소가 다른 배포본에서는 보이지 않습니다. 모두가 같은 신청 목록을 보려면 서버와 데이터베이스가 필요합니다.
  • 실습 때는 이름과 연락처에 가상의 정보만 넣습니다.
  • 중복 신청 같은 규칙은 요청에서 빼면 AI가 구현하지 않습니다. 데이터 정의표의 예외를 요청에 다시 넣어야 합니다.

RICE 정리

문제의 우선순위를 점수로 정하는 방법입니다.

  • Reach: 얼마나 많은 사람에게 영향이 있는가
  • Impact: 한 사람에게 얼마나 큰 영향이 있는가
  • Confidence: 위 추정을 얼마나 믿을 수 있는가
  • Effort: 해결에 드는 노력이 얼마나 큰가

점수는 (Reach x Impact x Confidence) / Effort로 계산합니다. 근거가 적으면 Confidence를 낮춰서 점수에 반영합니다. 같은 점수가 나온 문제는 근거가 더 확인되는 쪽을 먼저 보고, 확인되면 다시 계산합니다.

내가 직접 해 본 것

프로젝트 지침과 안/밖 비교

  • 같은 질문을 프로젝트 안과 밖의 새 대화에서 던져 답을 비교하는 질문을 만들었습니다. 비교 항목은 파일명 형식, 가설 표기 여부, 화면 이름 사용 여부 세 가지입니다.
  • 비교 결과는 아직 정리하지 못했습니다.

메모리와 예약 작업

  • 기획서 작성 팁(핵심 7원칙, 기본 뼈대 8항목, 피할 것)을 메모리에 저장했습니다.
  • 예약 작업은 사용한 채팅 화면에 관련 도구가 없어서 만들지 못했습니다.

컴퓨터 연결 실습

  • 컴퓨터와 연결이 끊긴 상태에서 바탕화면에 폴더 만들기를 요청하고, 웹 채팅과 데스크탑 앱에서 결과를 확인했습니다.
  • 연결이 없으면 폴더를 만들 수 없고, 대신 연결 방법을 안내해 줍니다.

올리브영 온라인몰 개선 제안서 (학습용 가정)

  • 검색해 보니 올리브영이 이미 앱에서 피부 진단을 출시한 것을 발견해서 문제 정의를 바꿨습니다.
  • 확정한 문제는 진단 결과가 검색 결과 화면과 상품 상세 화면에 이어지지 않아 처음 보는 상품을 고를 때 구매 확신을 얻기 어렵다는 것입니다.
  • 슬라이드는 요약, 시장 분석, 문제 정의, 해결 방안, 실행 계획의 다섯 챕터로 나누고, 페이지마다 어느 챕터인지와 무엇을 말하는지가 보이도록 고쳤습니다. IA 페이지와 와이어프레임 페이지도 따로 만들었습니다.
  • 구글 문서 PRD 템플릿 사본의 틀을 그대로 두고 문제 정의 파트 중심으로 간단히 채웠습니다. 데스크리서치 파트는 이번에 넘겼습니다.
  • PRD는 문제 60%, 설계 20%, 미정 20%로 배분하는 방식도 시도했습니다. 문제 파트에 힘을 싣고 설계는 방향만, 정해지지 않은 것은 표로 분리하는 방식입니다.

강사님 피드백

  • 외부 공유용 자료에는 가정이나 확인 필요 같은 나에게만 필요한 정보가 없어야 합니다.
  • 화려하게 많이 만든다고 좋은 것이 아니고, 정리되어 있어야 프로페셔널해 보입니다.
