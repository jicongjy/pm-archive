확장 프로그램은 무엇으로 이뤄지나

확장 프로그램은 웹페이지와 같은 HTML과 자바스크립트로 만들고, 설명 파일(manifest.json)과 권한이 더해진 것입니다. 한 사이트 안에서만 일하는 웹페이지와 달리 여러 사이트에서 일할 수 있어서, 할 수 있는 일도 많고 조심할 것도 많습니다.

파일하는 일
manifest.json이름, 버전, 권한, 처음 열 팝업 파일을 적어 둔 설명 파일. 크롬이 설치할 때 가장 먼저 읽음
background.js화면 뒤에서 기다리다가 우클릭 메뉴가 눌리면 선택한 문장을 저장
popup.html단추를 누르면 뜨는 작은 창의 생김새
popup.js저장한 문장을 카드로 보여 주고, 누르면 복사

아이콘 이미지를 넣으면서 파일은 4개에서 늘었습니다. 기획서를 먼저 쓰고, 그 기획서를 만들기 요청에 그대로 붙여 넣었습니다.

항목내 문장 모음
누가고객 문의에 같은 안내 문장을 자주 붙여 넣는 운영 담당자
반복되는 일안내 페이지를 열어 문장을 찾아 복사하기
할 일드래그 후 우클릭으로 저장, 단추를 누르고 카드를 눌러 복사
저장 위치와 개수내 크롬 안, 최대 30개
필요한 권한우클릭 메뉴(contextMenus), 저장(storage)
하지 않을 일바깥 서버로 보내기, 모든 사이트의 내용 읽기

먼저 알아 둘 말

용어쉬운 비유
매니페스트(manifest.json)확장 프로그램의 신분증. 이름, 버전, 쓸 권한을 적어 두고 크롬이 가장 먼저 읽음
권한크롬에게 "이것까지 해도 되나요" 하고 받는 허락 목록. 넓을수록 심사와 설치 경고가 커짐
압축해제된 확장 프로그램 로드스토어를 거치지 않고 내 컴퓨터 폴더를 바로 설치하는 단추. 개발자 모드를 켜야 보임
전용 목적이 확장 프로그램이 하는 한 가지 일을 적은 문장. 심사자는 권한이 이 목적에 꼭 필요한지 봄
개인정보처리방침어떤 정보를 모으고 어디에 보관하고 어떻게 지우는지 적은 공개 문서. 스토어가 주소를 요구함
UTM링크 끝에 붙이는 꼬리표. 어느 채널, 어느 캠페인에서 왔는지 GA가 읽음
단축 URL긴 UTM 주소를 짧게 줄여 주는 포장지. 누르면 원래 주소로 넘어가서 UTM 값은 그대로 남음

내 실습: 내 문장 모음(Phrasebook)

만든 순서

  1. 기획서를 붙여 넣어 4개 파일을 만들고, 권한은 contextMenus와 storage 두 개만 쓰도록 제한했습니다.
  2. 클로드 디자인으로 편집 가능한 시안 4장(밝은 화면, 어두운 화면, 빈 화면, 우클릭 저장 장면)을 만들었습니다.
  3. 설치 없이 흐름을 눌러 볼 수 있는 한 장짜리 시험 화면에서 사용자 흐름을 점검했습니다.
  4. 실제 출시할 수준으로 오류, 삭제와 수정, 알림 상황을 기획해 시험 화면에 반영한 뒤 같은 내용을 확장 프로그램 코드에 옮겼습니다.
  5. 압축 파일로 내려받아 크롬에 설치하고 시험하며 고쳤습니다.

크롬은 알림을 대신 띄워 주지 않습니다

복사나 저장이 끝나도 크롬은 아무 표시를 하지 않아서 알림은 모두 직접 만들어야 합니다. 알림 방식마다 권한 부담이 달랐습니다.

알림 방식필요한 권한선택
웹페이지 위에 알림 띄우기모든 사이트의 내용 읽기. 기획서의 "하지 않을 일"과 충돌쓰지 않음
크롬 바탕화면 알림알림 권한 추가쓰지 않음
아이콘 위 작은 표시(4초)추가 권한 없음사용
저장 직후 팝업 자동 열기추가 권한 없음. 크롬 버전과 창 상태에 따라 막힐 수 있음사용(막히면 아이콘 표시만 보임)
팝업 안의 알림과 방금 저장한 카드 강조추가 권한 없음사용

시험에서 나온 문제와 고친 것

구분증상원인과 해결
오류문장을 복사하면 성공 알림이 연달아 두 번 뜸복사 표시를 지우려고 화면을 다시 그릴 때 이미 떠 있던 알림이 처음부터 다시 나타남. 알림이 나타나는 움직임을 한 번만 보이게 수정
개선오래된 문장이 자동으로 지워진 뒤에 "삭제되었다"는 알림이 떠서 사용자가 무엇을 지울지 고를 수 없음30개가 가득 찬 상태에서 새 문장을 저장하면 지울 문장을 직접 고르는 화면을 보여 줌. 28개부터 "곧 가득 차요" 안내
시험 화면강조 테두리가 카드 바깥에서 잘림목록 영역이 바깥을 잘라 내고 있었음. 테두리를 카드 안쪽에 그리도록 수정
시험 화면우클릭하면 드래그한 선택 표시가 사라짐메뉴가 떠 있는 동안 선택한 문장에 표시를 따로 유지. 실제 크롬에서는 크롬이 정하는 부분이라 시험 화면에만 해당

문장을 저장할 때의 판단 흐름

[문장을 드래그하고 우클릭 -> 저장 선택]
        |
   <이미 저장된 같은 문장인가?>
     예 |            아니오 |
   맨 위로 올림        <저장된 문장이 30개인가?>
                        예 |          아니오 |
              [지울 문장을 고르는 화면]   [저장]
                        |                 |
                  고른 문장 삭제 후 저장 ---+
                        |
   [아이콘 표시 4초 + 팝업 안 알림 + 방금 저장한 카드 강조]

상단과 하단 정리

  • 상단: 제목 아래에 버전(v1.1.0)을 표시합니다. manifest.json의 버전을 그대로 읽어 오기 때문에 버전을 올릴 때 한 곳만 고치면 됩니다.
  • 하단: 브랜드 이름과 문의 링크를 둡니다. 브랜드 후보 6개(Phrasebook, Quill, 문장곳간, 한줄창고, Snippy, Stash) 중 제품 이름 "내 문장 모음"과 뜻이 같은 Phrasebook으로 정했습니다.
  • 문의 링크는 이메일 하나로 두고 누르면 새 메일 작성 창이 열립니다. 웹사이트가 없어서 웹사이트 링크는 값이 비어 있으면 숨겨지도록 했습니다.
  • 공개 저장소나 스토어에 올리면 코드 안의 문의 주소도 함께 공개됩니다.

저장 방식으로 본 확인 5~7

확인저장 방식에서 기대되는 결과
크롬을 닫았다 열어도 남아 있나chrome.storage.local은 크롬 프로필 안에 파일로 남아서 유지됨
다른 구글 계정으로 로그인한 크롬에서도 같은가local 저장은 계정 간에 동기화되지 않아서 그 크롬에는 따로 설치해야 하고 내용도 비어 있음. 동기화하려면 sync 저장을 써야 하고 그러면 방침에 적을 내용도 달라짐
시크릿 창에서는 어떤가확장 프로그램은 시크릿 창 사용을 허용해야 보이고, 허용해도 일반 창과 저장 공간이 따로임

스토어 출시 준비

플랫폼에 올리는 순간 그 플랫폼의 개발자 약관과 정책을 따라야 합니다. 내 크롬에 설치해서 쓰는 것은 계정, 비용, 심사가 필요 없지만, 스토어에 올리려면 개발자 계정(등록비 미화 5달러, 1회), 2단계 인증, 심사, 개인정보 공개가 모두 필요합니다. 진짜 출시한다는 마음으로 이름, 문구, 스크린샷을 준비했습니다.

  • 지인과 그룹은 medium이 아니라 campaign과 content로 갈랐습니다.
  • 값은 소문자와 밑줄로만 쓰고, 이름이나 한글, 공백은 넣지 않았습니다. 대소문자가 다르면 GA4에서 다른 값으로 집계됩니다.
  • campaign 끝의 2611은 다음 달에 다시 공유해도 회차가 구분되게 한 날짜입니다.
  • 메신저로 연 링크는 UTM이 없으면 직접 방문(direct)에 섞이기 쉬워서 개인 메시지 링크에도 붙입니다.
  • GA4에서는 보고서, 획득, 트래픽 획득에서 기준을 세션 캠페인으로 바꿔 봅니다. 실시간 보고서에서는 1~2분 안에, 일반 보고서에는 하루 정도 뒤에 반영됩니다.

  • UTM은 GA를 설치한 내 페이지로 가는 링크에만 붙입니다. 스토어처럼 남의 페이지로 바로 보내면 내 GA에서는 볼 수 없어서, 홍보 링크는 내 소개 페이지로 보냅니다.
  • 단축 URL은 UTM이 붙은 전체 주소를 먼저 만든 뒤 줄이고, 채널마다 짧은 주소를 따로 만듭니다. 짧은 주소 하나를 여러 채널에 쓰면 다시 섞입니다.
  • 단축 서비스가 세는 클릭 수와 GA 방문 수는 세는 방법이 달라서 숫자가 다를 수 있습니다. 성과는 GA 숫자로 봅니다.

배운 점

  • 크롬은 복사나 저장 알림을 대신 띄워 주지 않습니다. 웹페이지 위 알림처럼 눈에 띄는 방식은 더 넓은 권한이 필요해서, 권한을 늘리지 않는 방식(아이콘 표시, 팝업 안 알림)으로 알려야 합니다.
  • 사용자가 모르는 사이에 데이터를 지우면 안 됩니다. 한도가 찼을 때는 자동 삭제 대신 사용자가 고르게 해야 합니다.
  • 실제 크롬에서 눌러 보면 시험 화면에서 못 본 오류(알림 중복)가 나옵니다.
  • 스토어 입력란에 쓴 내용, 방침, 실제 코드가 서로 같아야 해서, 권한을 하나 늘리면 세 곳을 모두 고쳐야 합니다.
  • 공개 저장소에 올리면 코드 안의 연락처도 공개됩니다.
  • UTM은 medium 값에 따라 GA4 채널 분류가 달라지고, 대소문자가 다르면 다른 값으로 집계됩니다.

남은 일

  • 크롬 닫고 열기, 다른 구글 계정의 크롬, 시크릿 창에서 저장 내용이 어떻게 보이는지 직접 확인하고 결과 기록
  • 개인정보처리방침의 운영자 이름을 채운 뒤 깃허브 페이지스로 공개하고, 시크릿 창에서 로그인 없이 열리는지 확인
  • 앱 이름을 "내 문장 모음 (Phrasebook)"으로 정하면 manifest.json의 이름도 맞추기. 저장소에 라이선스 파일 추가 여부 정하기
  • UTM 링크를 실제로 공유하고 GA4 실시간과 세션 캠페인에서 들어오는지 확인(수집 후 반영까지 시간이 걸림)
  • UTM 주소를 단축해 GA 없이 조회수를 확인하는 방법 해 보기, 다른 단축 서비스 비교
  • 과제: 내 반복 업무로 확장 프로그램을 하나 더 만들어 깃허브에 올리고, 짝과 바꿔 설치해 보기(네트워크 탭에서 바깥 요청이 없는지 확인)
