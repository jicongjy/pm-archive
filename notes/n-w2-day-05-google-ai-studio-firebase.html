3-3. AI 스튜디오로 같은 Hello 페이지 만들기

  • 어제 볼트에 보낸 한 줄 요청을 AI 스튜디오에도 그대로 보내서 도구 차이를 비교했습니다. 요청이 같으니 결과가 다르면 도구 때문입니다.
  • 교안 실행 기록에서는 약 40초 만에 만들어졌고, 요청하지 않은 "브라우저 저장(localStorage)" 기능이 함께 붙었습니다. AI가 요청하지 않은 기능을 넣을 수 있으니 결과를 읽고 확인해야 한다는 점을 다시 확인한 대목입니다.
  • 회사나 학교 계정은 AI 스튜디오가 막혀 있을 수 있어 개인 지메일 계정을 쓰도록 안내받았습니다.

3-4. Firestore 연결 (심화)

  • 수업 중 강사 안내로 교안의 "새 프로젝트를 만들고 한 줄로 Firestore 연결하기"(수동 연결)는 심화 실습으로 정정되었습니다.
  • 핵심 주의점: Firestore 연결 창은 이미 있던 다른 프로젝트를 기본으로 골라 둘 수 있습니다. 그대로 누르면 그 프로젝트에 수업 데이터가 쌓이므로, 연결 창에서 수업용 프로젝트를 직접 골라야 합니다.
  • 저장 확인은 Firebase 콘솔의 'ai-studio-'로 시작하는 데이터베이스에서 컬렉션 안의 문서를 눈으로 봅니다.
  • 보안 규칙 오류(Missing or insufficient permissions)가 나면 규칙을 "아무나 읽고 쓰기"로 여는 것은 해결이 아닙니다. 오류 문장을 그대로 AI에게 붙여 원인을 묻습니다.

3-5. Publish로 공개하기

  • Publish를 누르면 Step 1에서 프로젝트와 결제 상태를 확인합니다. 구글 클라우드 계정 연결과 결제 계정 연결 두 가지가 중요한 항목이라고 안내받았습니다.
  • 개인 지메일 계정은 Starter Tier로 앱 2개까지 결제 계정 없이 공개할 수 있습니다. 회사 워크스페이스 계정, 유료 결제 이력이 있는 계정, 사용 기록이 너무 적은 새 계정은 대상이 아닐 수 있습니다.
  • 결제 수단을 등록했다면 구글 클라우드 콘솔 '예산 및 알림'에서 비용이 생기면 메일을 받도록 설정합니다.
  • 2026-09-14부터 제미나이 API 유료 사용은 선불(Prepay)로 바뀌었습니다(교안 기준, 2026-11-05 확인). 이 Hello 앱은 제미나이 API를 부르지 않아 충전이 필요 없습니다.
  • 고친 내용이 공개 주소에 안 보이면 Publish에서 Republish를 눌러야 합니다. 더 쓰지 않을 앱은 Unpublish합니다.

4. 직접 실습: 이벤트 신청폼 관리자 페이지

4-1. 만든 것

신청서와 관리자 페이지를 한 HTML 파일로 합쳐 만들었습니다. 한 번에 다 넣지 않고 기능을 하나씩 추가하며 확인했습니다.

  • 신청서: 접수 완료 화면, 같은 번호로 다시 신청하면 "이미 신청된 번호입니다." 안내
  • 관리자 입장: 비밀번호를 입력해야 들어갈 수 있는 화면
  • 관리자 CRUD: 신청 추가, 조회(기간 선택, 검색, 페이지 넘김), 수정, 삭제, 전체 삭제
  • 개인정보 표시: 이름, 전화번호, 이메일, 전달 사항은 일부를 가려서 표시
  • 개인정보 수집 이용 동의: 신청서에서는 필수로 받았지만 저장되지 않던 누락을 직접 발견해 고쳤고, 관리자 표에 "개인정보 동의" 열이 생겼습니다.

4-2. 개선하면서 내린 결정

  1. 관리자 화면에 불필요한 카드가 많고 간격이 넓어 스크롤이 길었습니다. 카드를 없애고 요약을 한 줄로 줄였으며, 그래프도 작은 막대로 줄였습니다.
  2. 데이터와 다른 정보가 섞여 있어서 "현황"과 "신청 명단" 두 영역으로 나누고, 각 영역을 접고 펼 수 있게 했습니다.
  3. 상단 제목, 탭 칩, 하단 관리 영역의 좌우 여백이 서로 달라서 같은 값으로 맞췄습니다.

4-3. 고민하고 정한 기준

정보를 마스킹하기 때문에 어떤 항목을 식별자로 둘지 고민했습니다. 관리자가 한 화면 안에서 원하는 정보를 한 번에 빠르게 파악하는 것을 최우선으로 두었고, 그래서 디자인과 간격을 최소화했습니다. AI로 만들면 블록으로 조합된 UI가 많이 나오는데, 내역과 리스트를 보고 관리하는 입장에서는 블록이 꼭 필요하지 않은 경우가 많다는 점을 알게 되었습니다.

관리자 페이지에서 지킬 기준은 다음과 같이 정리했습니다.

  • CSV 전체 다운로드 기능은 필수
  • AI가 낸 결과는 반드시 검증하고 확인하며 하나씩 개선
  • 데이터가 두 줄로 늘어지거나 좌우 스크롤이 생기지 않게 하는 가독성
  • 상단 그래프 등은 크게 차지하지 않게 구성

4-4. 한계와 남은 과제

  • 비밀번호 입장은 화면 입장만 막는 용도입니다. 비밀번호가 파일 소스 안에 들어 있어 소스를 열면 볼 수 있으므로 실제 운영에는 서버 쪽 보호가 필요합니다.
  • 이 HTML 파일의 데이터는 브라우저에만 저장됩니다. 여러 사람의 신청을 한곳에 모으려면 Firestore나 구글 시트 같은 저장소가 필요합니다.
  • 심화 과제인 CSV 전체 다운로드(관리자 화면 항목과 CSV 컬럼 항목에 차이를 두고, 그 이유를 사용자 입장에서 생각해 보기)는 이 기록 기준으로 구현이 확인되지 않았습니다. 남은 일입니다.
  • 관리자가 대신 신청을 추가할 때 개인정보 동의를 어떻게 처리할지는 아직 정하지 않았습니다.
  • 모바일 화면은 눈으로 확인하지 못했습니다.

7. 겪은 문제

  • AI 스튜디오 무료 일일 한도가 소진되어 오후에 결과가 나오지 않는 경우가 있었습니다. 대안은 다른 계정으로 진행하거나, 소스 코드를 깃허브에 올려 두고 클로드나 챗지피티에서 이어서 작업하는 방법입니다.
  • 공유 링크는 시크릿 창(깃허브 비로그인 상태)에서 열어 보면 다른 사람 입장에서 보이는지 더블 체크할 수 있습니다.
  • 배포한 사이트에서 신청해도 오류가 나거나 관리자 페이지나 시트가 안 되는 경우에는 오류 문장을 그대로 AI에게 붙여 원인을 묻는 방식으로 접근합니다.

8. 오늘의 회고

1. 이미 알고 있었던 내용

관리자 페이지를 만들어 본 경험이 있습니다. AI 스튜디오로 영상을 만들어 보거나, 파이어베이스로 배포를 조금 해 본 경험도 있습니다.

2. 새로 배운 내용

앱스스크립트를 AI 자동화에만 써 봤는데, 웹페이지를 만들고 데이터를 연결하는 데도 쓸 수 있다는 것은 오늘 처음 알게 되었습니다. AI 스튜디오 자체에서 배포할 수 있다는 것도 처음 알았습니다. AI 스튜디오 안에서는 파이어베이스나 스프레드시트 같은 구글 서비스가 재로그인이나 다른 인증 없이 한 번의 클릭으로 연동된다는 것도 알게 되었고, 구글 로그인과 인증도 정말 편했습니다. 관리자 화면은 일반 화면과 달리 한 화면에서 정보를 빠르게 파악하는 가독성이 우선이라는 차이를 알게 되었습니다.

3. 새롭게 도전/연습할 목표
