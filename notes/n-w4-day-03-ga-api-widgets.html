오늘 다룬 내용

GA 숫자는 무엇을 세는가

GA 보고서 첫 화면의 활성 사용자는 정해진 기간에 사이트에 참여한 순 사용자 수입니다. GA에서도 빠지는 사용자가 있어서 숫자를 그대로 믿으면 안 됩니다.

빠지는 경우내용
집계 기준에 따른 제외알려진 봇의 방문은 자동으로 빼고, 사용자 수가 적은 줄은 개인 보호를 위해 보고서에서 숨김
기술적 수집 누락광고 차단 프로그램이 태그를 막거나, 태그를 넣기 전의 방문은 기록되지 않음

GA를 알면 "이 지표가 정말 정확할까?", "가설을 확인하려면 지표를 어떻게 계산할까?"를 물을 수 있습니다.

인기 글을 지표로 바꾸기

"무엇이 트렌디한지"처럼 넓은 목적으로는 무엇을 셀지 정할 수 없어서 취소하고, 지표마다 계산식이 나오도록 좁혔습니다.

측정할 지표계산 방식필요한 이벤트
글별 평균 체류 시간글에서 나간 시각 빼기 글을 연 시각글 열기, 글에서 나가기
완독 여부끝까지 읽은 수 나누기 글을 연 수글 열기, 끝까지 읽음(기준은 내가 정함)
반응이 높은 글좋아요, 댓글, 스크랩 수반응 이벤트(기능이 없으면 기능부터 필요)

개발자와 이야기할 때

상황방법
"GA 태그만 심어 주세요"라고만 요청하는 경우가 많음기획서에 목표, 지표, 계산 방식, 확인할 이벤트, 추가할 이벤트 목록을 담아 간다
측정이 가능한지 모름마케터와 기획자가 먼저 같이 찾아본다
이벤트 택소노미를 어떻게 짤까이벤트를 나열하는 일이 아니라 목적과 지표에서 필요한 이벤트를 고르는 일

이벤트 이름은 이름만 읽어도 무슨 행동인지 알 수 있어야 하고, 새로 만든 이벤트에는 공통 접두어를 붙이면 GA가 자동으로 세는 이벤트와 구분됩니다.

주소가 하나인 사이트의 문제

바이브코딩으로 리액트로 만든 사이트는 대부분 주소가 바뀌지 않고 화면만 바뀝니다. 이런 사이트는 GA의 기본 자동 측정만으로는 페이지 이동을 잡지 못해서, 화면이 바뀔 때마다 페이지 조회를 직접 보내야 합니다. 페이지 제목과 주소가 페이지마다 달라야 GA 보고서에서 글별로 구분됩니다. 클로드 코드에 "내 사이트가 어떤 구조와 언어로 개발되어 있고 GA 사용에 이슈가 없는지"를 직접 물어 확인했습니다.

내 실습 1: 블로그 2차 개선

만든 순서

  1. 현재 블로그의 구조와 GA 이슈, 인기 글 측정 가능 여부를 질문하고 개선할 점을 정리했습니다.
  2. 2차 개선 PRD를 기획하고 결정이 필요한 것을 정했습니다.
  3. 제출용 HTML로 PRD를 쓰고, 우선순위와 이벤트, 신규 기능 분류를 보기 좋게 다시 정리했습니다.
  4. PRD를 바탕으로 이벤트와 기능을 구현하고 로컬에서 이벤트 값을 직접 읽어 확인했습니다.

PRD에서 정한 것

결정내용
반응 기능 범위좋아요와 스크랩만 하고 댓글은 후속 목표로 이동
대시보드외부 툴 없이 GA에서 바로 가져오기
링크 복사복사한 주소에 UTM을 붙임
완독 기준읽는 시간의 40%이고 최소 10초로 시작
문서 형식HTML 파일 하나, 텍스트와 표 중심
문서에서 뺀 것개인 채팅 결정 사항, 단계별 일정, GA 콘솔 설정과 맞춤 측정기준 설명
스크랩 목록 보기후속 범위로 이동

작성하면서 헷갈렸던 것은 두 가지였습니다. "측정 가능 여부"를 PRD에 넣는 것이 맞는지, 맞춤 측정기준과 측정항목도 이번에 새로 만드는 이벤트인지였습니다. 맞춤 측정기준은 이벤트가 아니라 GA 콘솔에서 하는 등록이라는 설명을 듣고, PRD에는 이벤트만 남기고 설정은 별도 문서로 분리했습니다.

구현한 것

요구구현
글 정보 보강글 관련 이벤트에 발행일과 읽는 시간을 함께 보냄
완독본문 90% 지점이고 화면이 앞에 있던 활성 시간이 읽는 시간의 40% 이상, 최소 10초일 때 방문당 한 번
체류 시간15, 30, 60, 120초 지점에 이벤트
공유와 검색링크 복사 클릭, 검색 입력이 멈춘 뒤 검색어와 결과 수
반응글 아래 좋아요와 스크랩 버튼. 익명 로그인으로 방문자를 구분하고 처음 누를 때만 계정을 만듦
내부 방문관리자로 로그인한 브라우저는 이벤트를 보내지 않음

보안 점검에서 지적받고 고친 것

지적고친 것
비공개 글과 임시저장 글이 이벤트로 나갈 수 있음비공개와 임시저장 글은 이벤트를 보내지 않게 함
검색어에 전화번호, 이메일이 들어가면 외부로 나감이메일, 전화번호, 긴 숫자, 주소 모양이면 "제외됨"으로 보내고 50자로 자름
하이픈이나 공백이 낀 전화번호, 전각 숫자는 걸러지지 않음판별 범위를 넓히고 전각 숫자를 일반 숫자로 바꿔서 확인, 숫자 기준은 6자리로 낮춤
방문자 계정 ID가 외부 서비스로 나감되돌릴 수 없는 해시 값으로 바꿔 보내고, 해시를 만들 수 없으면 아바타를 숨김

고친 뒤에도 같은 종류의 지적이 여러 번 이어졌습니다. 한 번 고치고 끝내지 않고, 우회하는 입력(공백, 전각 숫자)까지 따져 보는 것이 점검의 핵심이었습니다.

내 실습 2: 무료 API 붙이기

API어디에 붙였나정한 것과 확인한 것
명언(dummyjson)헤더 안, 로고와 메뉴 사이의 흐르는 띠한국어 명언 API는 서비스가 중단되었고, 다른 하나는 브라우저 호출 허용 표시가 없고, 또 하나는 응답이 없어서 dummyjson만 정상이었음. 실패하면 띠를 숨김
아바타(DiceBear)좋아요 한 사람들실습이라 주소로 불러오는 방식으로 함. 라이브러리로 직접 만들면 외부 요청이 없다는 설명을 들었지만 이번에는 쓰지 않음. 스타일은 출처 표기가 필요 없는 흑백 선화로 고름
공휴일(공공데이터포털)메뉴 줄 시계 왼쪽의 "다음 공휴일 D-일수"키가 있으면 공공데이터포털 특일 정보를 쓰고, 없거나 실패하면 키가 필요 없는 Nager.Date로 대체. 키는 저장소의 비밀 값에 둠. 잘못된 키로 실행해 403 뒤 대체되는 것까지 확인

OpenWeather 세계 날씨 사이트

도시 이름과 나라를 넣으면 지금 날씨와 5일 예보, 앞으로 24시간 기온 곡선이 나오는 한 장짜리 사이트입니다. 처음에는 숫자와 작은 그림만 있어서 날씨 앱 같은 시각화가 없다고 요청해 큰 하늘 카드, 습도 게이지, 바람 방향, 일출 일몰 호로 바꿨습니다.

  • 같은 이름의 도시가 여러 곳이면(서울이 한국과 미국 일리노이에 모두 있음) 알맞은 곳을 눌러 고르게 했습니다.
  • 인증 키는 파일에 넣지 않고 화면 위쪽에 붙여 넣으면 쓰는 브라우저에만 저장되게 했습니다. 이 저장소는 공개라서 파일에 키가 들어가면 그대로 노출되기 때문입니다.
  • 가입 직후에는 키가 켜지기까지 최대 2시간쯤 걸려서, 그동안은 "아직 쓸 수 없다"는 안내가 나옵니다.
  • 가짜 응답으로 검색, 지역 고르기, 섭씨 화씨 전환, 키 오류 안내는 확인했지만 진짜 키로는 아직 돌려 보지 못했습니다.

라이브러리 확인과 시안

현재 블로그가 쓰는 것을 package.json과 대조해 확인했습니다.

구분쓰는 것
화면과 빌드React 19, Vite 8
라이브러리화면 이동(react-router-dom), 로그인과 저장(firebase), 글쓰기 에디터(Tiptap), 본문 정화(DOMPurify)
쓰지 않는 것Tailwind 같은 스타일 라이브러리, 상태 관리, 테스트와 린트 도구

코드는 바꾸지 않고 아티팩트로 시안 두 가지를 만들었습니다. Tailwind CSS로 다시 꾸민 홈 화면과, 관리자 화면의 조회수 시안(간단한 목록형과 Chart.js 차트형)입니다. 시안의 숫자는 모두 예시이고, 실제로 붙이려면 GA 데이터를 서버 쪽에서 가져오는 부분을 따로 만들어야 합니다.

배운 점

  • 주소가 하나인 사이트는 화면이 바뀌어도 GA가 이동을 잡지 못해서, 이동마다 페이지 조회를 직접 보내야 합니다.
  • 인기 글은 하나의 숫자가 아니라 체류 시간, 완독, 반응처럼 지표마다 계산 방식과 기준을 정해야 합니다. 완독의 기준(읽는 시간의 몇 퍼센트)은 내가 정합니다.
  • 맞춤 측정기준은 이벤트가 아니라 GA 콘솔에서 하는 등록입니다. PRD에는 이벤트와 요구사항을 쓰고 콘솔 설정과 일정은 따로 둡니다.
  • 외부 API를 붙이면 방문자를 구분하는 값이 밖으로 나갈 수 있어서, 되돌릴 수 없는 값으로 바꿔 보내야 합니다.
  • 키가 필요 없는 API도 서비스가 중단되었거나 브라우저에서 호출할 수 없는 경우가 있어서, 붙이기 전에 직접 요청해 봐야 합니다.
  • 공공데이터와 외부 API는 키가 없거나 실패할 때 어떻게 보일지(대체 데이터, 숨김)까지 정해 둬야 화면이 깨지지 않습니다.

남은 일

  • 반응 기능 켜기: Firebase에서 익명 로그인을 사용하도록 설정하고, 수정한 보안 규칙을 적용한 뒤 여러 사람이 좋아요를 눌렀을 때 아바타가 모두 보이는지 확인
  • 공공데이터포털 키를 저장소 비밀 값에 등록한 뒤 배포를 수동으로 한 번 실행해 공휴일이 실제 키로 받아지는지 확인
  • 맞춤 측정기준 등록과 GA 실시간, 일반 보고서에서 새 이벤트가 들어오는지 확인
  • 날씨 사이트를 진짜 키로 돌려 보기
  • 조회수 차트 시안을 GA 데이터와 연결해 관리자 화면에 붙이기
  • 아바타를 라이브러리 방식으로 바꿔 외부 요청 없이 만들어 보기
