2. 뤼튼과 수노 실습

2-1. 실습 구성

  1. 실습1. 뤼튼을 써 보고 결과물 공유하기
  2. 실습2. 클로드 인 크롬에서 피그마 또는 html 파일로 뤼튼 결과와 챗지피티, 제미나이 결과를 합쳐 최종 상품 상세페이지 이미지를 1벌 만들기
  3. 실습3. 수노를 써 보고 결과물 공유하기

2-2. 뤼튼 (상세페이지 도구)

  • 사용한 화면: 뤼튼 도구 중 상세페이지
  • 링크: https://wrtn.ai/tools/67b2e7901b44a4d864b127b5
  • 입력한 내용: 상품 한 줄 소개, 포함되어야 할 상품 정보, 요청사항(톤, 구성 순서, 수형 잡는 법 안내 방식, 근거 없는 표현 금지, 섹션별 제목과 설명 길이)
  • 사용 느낌
  • 카테고리가 분명해 사용자가 목적에 맞게 쓰기 좋았습니다.
  • 결과물 방향이 제가 넣은 프롬프트와 완전히 맞지 않아, 내부에 어느 정도 규격화된 템플릿이 있는 것 같았습니다.
  • 결과를 받은 뒤 원하는 방향으로 수정하는 부분이 더 세밀하면 좋겠다고 느꼈습니다. (화면 오른쪽 위에 고쳐쓰기 버튼이 있으니 직접 써 보고 확인이 필요합니다.)
  • 결과물에서 확인한 점
  • 요청한 구성 순서를 그대로 따르지 않았습니다.
  • 근거 없는 표현 금지를 요청했는데도 존재하지 않는 후기 문구가 맨 앞에 들어갔습니다.
  • 입력하지 않은 배송 기간 안내가 들어갔고, 본문에 중국어가 섞여 있었습니다.

2-3. 수노

  • 만든 곡: Cold Start (장르 태그 인디 록)
  • 링크: https://suno.com/s/1yjYPSskFpjuwReO
  • 사용 느낌
  • 빠르고 간편하게 노래를 만들 수 있어 좋았습니다.
  • 처음에 명령어를 입력할 때 스타일과 가사를 함께 입력해 버려 헷갈렸습니다. 모든 과정에서 입력 단계가 더 명확하게 보이면 좋겠다고 느꼈습니다.
  • 결과물을 수정할 때 금지, 필수 같은 칸이 있으면 원하는 방향으로 정확하게 고칠 수 있을 것 같았습니다.
  • 확인 필요: 소리는 직접 들어 보고 베이스 시작 여부를 확인해야 합니다.

2-4. 사용자와 생산자 입장 소감

  • 사용자 입장: 입력 칸이 정해져 있어 시작은 쉽지만, 결과가 의도와 다르게 나왔을 때 세밀하게 고치기 어렵습니다.
  • 생산자 입장: 입력 항목과 결과 구조를 어떻게 설계하느냐가 결과 품질을 좌우하고, 생성 후 수정 기능이 필요합니다.

3. 구글 AI 스튜디오 관리자 페이지 구축

3-1. 실습 구성

  1. 실습1. 플랜모드로 질문하며 요구사항 정리
  2. 실습2. 관리자 페이지 UI 구축
  3. 실습3. 세부 기능 구축과 테스트
  4. 실습4(추가). 관리자 페이지 진입 시 구글 로그인으로 진입
  5. 배포 후 확인: 실서비스 주소에서 로그인, 새 시크릿 창에서 테스트, 소스코드를 깃허브 저장소에 올리기

3-2. 만든 서비스: 오늘의 독서 메뉴

  • 손님 화면: https://reading-menu.ai.studio/
  • 관리자 화면: https://reading-menu.ai.studio/admin
  • 깃허브 저장소: https://github.com/jicongjy/jicongjy-multicampus-aistudio-bookservice
  • 만든 기능
  • 관리자 콘솔에서 감정 분석과 도서 추천 이유의 프롬프트를 수정
  • AI 모델 선택과 키 입력 설정 메뉴
  • 감정별 도서 목록 추가, 수정, 삭제
  • AI 호출 기록과 지연시간 확인
  • 도메인 뒤 /admin 주소로만 접속하고, 구글 로그인으로 진입
  • 파비콘(브라우저 탭 아이콘) 추가

3-3. 로컬 테스트에서 겪은 문제

  • 증상: 구글 로그인 실패, Firebase: Error (auth/unauthorized-domain)
  • 원인: 로그인을 요청한 접속 주소가 파이어베이스의 허용 도메인 목록에 없을 때 발생합니다.
  • 해결 방향: 파이어베이스 콘솔의 Authentication, 설정, 승인된 도메인에 localhost를 추가하고, http://localhost:3000 주소로 접속해서 다시 시도합니다.
  • 배운 점: 로컬에서 테스트할 때는 파이어베이스에 허용 주소를 추가해야 합니다.

3-4. 확인이 필요한 항목

  • 코드에 API 키가 직접 들어가 있지 않은지 점검하고, 있다면 코드 밖에 보관합니다. 공개 저장소에 올리면 누구나 볼 수 있어서 올리기 전에 반드시 확인합니다.
  • 관리자 로그인에서 허용할 이메일을 본인 계정으로 제한했는지 확인합니다.
  • 시크릿 창에서 /admin에 접속해 로그인 화면만 보이는지 확인합니다.

4. 클로드 데스크톱 앱과 로컬 환경

4-1. 데스크톱 앱 실습

  1. 클로드 데스크톱 앱 설치, 챗과 코드 메뉴 확인
  2. 설정에서 파일시스템 기능 확인, 교육 계정(프로 플랜 기업 계정) 로그인 확인
  3. 바탕화면에 AIPM 소스코드 폴더 만들기, 폴더 열기, 폴더 안에 새 폴더 만들기
  4. 선택: 파일 만들기, 삭제, 이동, 이름 변경
  5. 브라우저 클로드에서도 데스크톱 앱 설치 후 파일시스템 제어가 가능한 것을 확인

4-2. 클로드 기능 흐름 (강의 정리)

  1. 최신 정보를 찾는 웹검색
  2. 지식과 참조로 업무 최적화
  3. 반복 프롬프트를 줄이는 스킬
  4. 업무 자동화를 위한 예약과 스케줄링
  5. 정해진 앱을 넘어 더 많이 연결하는 커넥터와 확장프로그램
  6. 크롬을 직접 움직이는 클로드 인 크롬
  7. 파일시스템을 다루는 데스크톱 앱

4-3. 로컬 서버 실행

  1. 터미널(맥) 또는 파워셸(윈도우)을 여는 방법
  2. 헬로 페이지를 로컬 서버로 실행해 127 주소로 접속
  3. 인터넷 없이도 실행되는 이유와 인터넷 연결 없이 테스트하는 방법 질문
  4. 마음 책방 소스코드를 내려받아 폴더에 정리하고 로컬에서 실행
  5. 개발자도구 네트워크 탭에서 제한 없음(No throttling)을 두고 보이는 부분과 동작하지 않는 부분 확인
  6. 개발자도구 콘솔에 오류가 나면 전체 화면을 캡처해 클로드에게 질문하고 결과를 스레드에 공유

4-4. 개발자도구 네트워크 탭 읽는 법

  • 맥 단축키 Cmd + Option + I로 개발자도구를 열고 Network 탭을 선택합니다.
  • 맨 아래 한 줄에서 요청 개수, 받은 데이터 크기, 로딩 완료 시간을 볼 수 있습니다.
  • Status 200은 성공, 304는 저장된 것을 사용, 빨간 줄은 오류입니다.
  • Offline으로 바꿔 새로고침하면 인터넷이 필요한 부분(구글 폰트, 구글 로그인, AI 기능)이 어떻게 달라지는지 비교할 수 있습니다.
  • 과제 문구의 제한 없음은 기본값이므로, 비교 대상이 오프라인인지 강사님께 확인이 필요합니다.

5. 회고

1. 이미 알고 있었던 내용

  1. 뤼튼 초기 버전 사용 경험
  2. 수노라는 AI 노래 서비스의 존재
  3. 터미널과 로컬 환경에서 테스트하는 방법

2. 새로 배운 내용

  1. 뤼튼에 구성 순서와 금지 사항까지 적어 요청해도, 결과물에 요청하지 않은 후기 문구가 들어가고 중국어가 섞이는 등 지시가 그대로 지켜지지 않을 수 있어서 AI 결과물은 반드시 직접 검수해야 한다는 것을 알게 되었습니다.
  2. 서비스에 정해진 입력 칸과 내부 템플릿이 결과의 방향을 좌우한다는 것을 알게 되었습니다. 서비스를 만드는 입장에서는 입력 항목과 결과 구조를 어떻게 설계하느냐가 품질을 결정한다고 생각하게 되었습니다.
  3. 수노는 스타일과 가사를 구분해서 입력해야 하는데 한꺼번에 넣어 헷갈렸던 경험으로, 입력 단계를 명확하게 보여 주는 것이 사용자 경험에 중요하다는 것을 알게 되었습니다.
  4. 로컬에서 테스트할 때 구글 로그인 오류가 나면 파이어베이스에 허용 주소를 추가해야 한다는 것을 알게 되었습니다.
  5. 개발자도구의 네트워크 탭에서 요청과 응답을 확인하는 방법을 알게 되었습니다.

3. 새롭게 도전/연습할 목표

  1. 교육 계정은 클로드 코드를 쓸 수 없는 줄 알았는데 데스크톱 앱에 로그인하니 가능했습니다. 깃허브를 연결해 강의 노트를 정리하면 자동으로 깃허브에 올라가게 해 보고 싶습니다.
  2. 그 밖에 교육에서 들은 내용도 자동으로 정리되게 만들어 보려고 합니다.
