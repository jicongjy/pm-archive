쇼핑몰 상담 챗봇을 만들어 내 컴퓨터에서 AI로 돌려 보고, 시험 케이스 32건과 학습조 피드백으로 고친 뒤, 대화 기록과 지침을 파이어베이스로 옮겨 인터넷 주소로 배포했습니다.

챗봇 탭 4개 비교

탭주제답하는 방식배운 점
탭 1화면만 있음미리 정한 단어를 찾아 미리 쓴 답을 꺼냄. AI 없음항상 같은 답이라 빠르고 안전하지만 예상 밖 질문엔 기본 안내문만 나옴
탭 2주제 제한 없음AI가 규칙과 참고 자료 없이 자유롭게 답함서비스로 쓰기 어려움. 정보가 없어도 그럴듯하게 지어낼 수 있음
탭 3쇼핑몰로 제한정보와 규칙에 맞춰 답함주제 밖 질문과 모르는 질문을 안내로 막을 수 있음
탭 4내 주제와 화면 개선표에서 답할 수 있으면 즉시 조회, 아니면 AI가 규칙 안에서 답함이번 실습의 중심. 퇴근 후 8시 스토어로 정함

탭 4를 키운 단계별 요구

단계요구기준
2차탭 4를 내 주제로 바꾸고 화면을 개선. 생성형 AI가 질문에 어떻게 답하는지 플로우차트로 그리기새 대화에서 해도 됨
3차실제 상품 데이터를 참고해 AI 상담원이 답하게 하기. 현재 소스코드가 상품 데이터를 무엇에서 가져오는지 묻고, 상품 목록, 재고, 주문 내역, 배송 추적 정보를 가상으로 각 10건 만들어 관리자 페이지에서 적용하고 고치기배송 문의가 핵심. 사용자의 기대치는 채팅으로 즉시, 빠르게 내 배송을 조회하는 것. 참고한 펫프렌즈의 상담 연결 방식보다 빨라야 함
4차소스코드를 내 컴퓨터로 옮겨 클로드 코드 메뉴에서 이어서 작업. 프로젝트 폴더의 설정 파일(.env)에 공유받은 API 키를 넣고 로컬에서 AI 챗봇 테스트실행한 뒤 테스트 보고서 공유

먼저 알아 둘 말

용어쉬운 비유
응답 정책표상담원 업무 매뉴얼. 질문 종류마다 어떻게 답할지 미리 적어 둔 표
즉시 조회창고 장부를 바로 펼쳐 보고 답하기. 재고, 주문, 배송처럼 표에 있는 값
로컬 서버내 컴퓨터 안에 둔 심부름꾼. 키를 들고 대신 AI를 불러 줌
운영자 지침관리자가 나쁜 답을 보고 남기는 "이렇게 답하세요" 쪽지. 다음 답변에 붙음
테스트 케이스시험 문제 한 문항. 입력, 기대 결과, 실제 결과를 같은 칸에 적음
Firestore인터넷에 둔 공용 장부. 새로고침하거나 다른 기기에서 열어도 기록이 남음

내 실습: 셀렉트마켓 채팅 탭 4

진행 순서

  1. 4개 탭이 각각 어떻게 답하는지 플로우차트와 응답 정책표로 정리
  2. 상품, 재고, 주문, 배송 가상 데이터를 각 10건씩 만들고 관리자 화면에서 고칠 수 있게 연결
  3. 내 컴퓨터에 작은 서버를 두어 AI 호출을 맡기고, 키는 서버에만 보관
  4. 대화 기록 저장, 답변 신고, 관리자 피드백으로 쌓는 운영자 지침 추가
  5. 시험 케이스 32건으로 테스트 보고서 작성
  6. 대화 기록, 지침, 스토어 표를 파이어베이스로 옮겨 인터넷 주소로 배포

답하는 방식 나누기

표에서 답할 수 있는 질문(재고, 주문, 배송, 환불)은 AI 없이 즉시 조회하고, 표에 없는 질문만 AI가 답하게 했습니다. 빠르게 답해야 하는 질문과 말을 풀어서 해야 하는 질문을 나눈 것입니다.

로컬에서 실제 서비스로: 배포 순서

  1. 내 소스코드를 깃허브로 옮긴다.
  2. 깃허브에 올린 코드를 파이어베이스와 연동해 배포한다.

배포 실습은 세 단계였습니다. 새로고침하거나 프로필이 바뀌면 사라지는 임시 저장소를 전부 파이어베이스로 옮기기, API 키를 파이어베이스에 안전하게 보관하는 방법(선택), 배포된 주소 확인.

배포하면 달라지는 것

항목로컬파이어베이스 배포
대화 기록브라우저 임시 저장. 새로고침하거나 프로필이 바뀌면 사라짐파이어스토어에 저장
운영자 지침내 컴퓨터의 파일파이어스토어에 저장
관리자누구나 버튼으로 진입구글 로그인과 관리자 명단에 있는 계정만
AI 답변서버가 키로 호출동작 안 함. 무료 요금제에는 키를 안전하게 둘 서버가 없음

테스트와 학습조 피드백

내 테스트 결과(수정 전 기준)

시험 케이스 32건을 직접 돌려 봤습니다.

결과건수내용
합격23건강, 개인정보, 범위 밖 질문은 응답 정책표대로 안내
보완8주문번호 여러 개, 주문과 가격 요청 안내, AI 응답 지연 등
불합격1재고를 물은 뒤 다른 질문을 하면 대화가 막힘
  • 원인: 재고를 물은 뒤의 대기 상태에서는 다른 주제의 질문도 표가 먼저 받아서 AI까지 넘어가지 못했습니다.
  • AI 답이 한 번 36.8초 걸렸는데, 그동안 중단할 방법이 없었습니다. 시간 제한을 두는 것이 보완 항목입니다.

테스트 보고서를 쓸 때 들은 안내

  • 보고서를 쓰다 보면 내 기획 의도와 맞지 않는 테스트 항목이 나올 수 있습니다. 그때는 기획 의도부터 다시 확인하고, 보고서의 항목도 함께 고쳐야 합니다.
  • 수업에서 소개된 다른 수강생의 기능 테스트 보고서는 기능마다 예시 이미지, 입력, 기대, 결과를 같은 형식으로 썼습니다. 공이 많이 들지만 실전에서 요구되는 수준이라는 평가였습니다.
  • 다른 수강생이 만든 챗봇 관리자 화면도 참고 예시로 소개되었습니다.

학습조에서 받은 피드백과 내 대응

오후에 학습조원들이 직접 써 보고 남긴 문제입니다.

피드백원인과 대응
상품 번호와 함께 "교환하고 싶어요"를 보냈는데 배송 조회와 같은 답이 나옴주문번호가 있으면 무엇을 물었든 배송 조회로만 답하는 빠른 답변 단계가 교환, 환불 확인에 닿지 못했습니다. 질문 의도를 먼저 가르도록 고쳤습니다.
결제 안내를 물어도 안내 페이지나 정보로 이어지지 않음정책과 지침을 보완
상품별 비교 기준(몸 쓰기, 말 많이 하기, 비용)이 상품에 따라 안내되지 않음지침에 비교 기준을 넣어 보완
상담원 연결 버튼이 고객센터 안내만 보여 주고 실제 연락처와 이어지지 않음상담원 연결을 가상으로 구현
재고가 얼마 없을 때 비슷한 제품 추천을 요청하면 "상품을 찾을 수 없다"고 답함관련 제품 탐색 개선
배송비와 배송 소요 기간을 물었더니 같은 문장이 중복됨답변 규칙에서 중복 제거

이 문제들을 고쳐서 다시 배포하고 다시 테스트했습니다. 내가 놓친 입력을 다른 사람이 찾아 준 것이 가장 큰 도움이었습니다. 혼자 테스트할 때는 "한 번에 하나씩, 정해진 순서로" 입력하게 되기 때문입니다.

운영 질문 정리

출시했다고 가정하면 관리자 화면에 더 저장해야 할 정보는?

  • 바로 저장할 수 있는 기능: 챗봇 대화 기록, 챗봇 사용자가 누구인지 기록
  • 새로 필요한 기능: 잘못된 답변 신고, 관리자가 이상한 답변을 고칠 수 있는 피드백

한 달 운영한 뒤 V2를 개선하려면 PM이 볼 데이터는?

  • 어떤 대화 목록이 있었는지
  • 잘못된 대화에 대한 신고 통계(신고율, 사유별 건수)

두 질문의 답을 관리자 콘솔의 "대화 기록" 화면과 "지침" 화면에 넣어 두었습니다.

API 키와 사용 비용

  • 수업 중에는 공유받은 키를 프로젝트 폴더의 .env 파일에만 넣고 실습했습니다. 키 사용은 당일 밤 12시까지였습니다.
  • 수업에서 공유된 사용량 화면 기준으로, 오후 3시 40분 무렵까지 학습자 전체가 테스트한 비용이 1달러가 안 되었습니다. 다음 날 아침에는 전날 저녁에 복습한 만큼 조금 늘어 있었습니다.
  • 키의 사용량과 비용은 키 주인에게 쌓이므로, 클로드 API를 쓸 때 이 정도 규모를 예상치로 참고할 수 있습니다.

이후 교안에 더해진 내용 (당일에는 하지 않음)

수요일에 교안을 다시 확인하니 월요일 교안에 아래 내용이 더해져 있었습니다. 월요일 수업 안내에는 없던 부분이라 직접 해 보지는 않았고, 읽고 정리만 해 둡니다.

구분내용
프롬프트 엔지니어링챗봇의 답이 마음에 들지 않으면 모델이 아니라 함께 보내는 지시문(시스템 프롬프트)을 고칩니다. 지시문은 역할, 지킬 규칙, 모를 때, 말투와 예시 답변, 참조 자료의 다섯 칸으로 읽습니다. 시험 문항은 정책 답변, 데이터 조회, 범위 밖 질문, 프롬프트 인젝션, 개인정보로 나눠 만들고, 한 번에 한 곳만 고친 뒤 시험지를 모두 다시 시험합니다.
RAG질문이 오면 자료에서 필요한 부분만 찾아 질문과 함께 AI에게 보내고, 그 자료를 근거로 답하게 합니다. 답이 틀리면 지시문 문제인지 자료를 찾는 문제인지 먼저 나눕니다.
배포 요금제Cloud Functions와 Secret Manager는 쓴 만큼 내는 Blaze 요금제에서만 켤 수 있습니다. 결제 계정을 연결하므로 사용량을 확인하고, 실습이 끝나면 프로젝트를 지워 멈춥니다.
localhost와 127.0.0.1둘 다 내 컴퓨터를 가리키지만 브라우저는 서로 다른 사이트로 봐서, 한쪽에서 나눈 대화가 다른 쪽에는 보이지 않습니다.
키를 두는 곳프롬프트에 붙여 넣으면 대화 기록에 남고 코드 파일에 적힐 수 있어 안 됩니다. 내 컴퓨터에서는 .env, 구글 AI 스튜디오에서는 시크릿이 같은 생각입니다.

배운 점

  • 표로 답할 수 있는 질문과 AI가 풀어야 하는 질문을 나누면 빠르면서도 비용이 적게 듭니다.
  • 시험 항목이 기획 의도와 어긋나면 보고서만 고칠 게 아니라 기획부터 다시 확인해야 합니다.
  • 무료 요금제(Spark)로 배포하면 키를 안전하게 둘 서버가 없어서 AI 답변은 동작하지 않습니다. 서버 일을 하는 Cloud Functions와 키 보관소 Secret Manager가 Blaze 요금제에서만 켜지기 때문입니다. AI 답변까지 배포하려면 서버와 비밀값 보관이 더 필요합니다.
  • 관리자 화면에서 나쁜 답변을 신고받고 고쳐 쓰는 방식으로, 서비스를 낸 뒤에도 AI 답변을 계속 개선할 수 있습니다.
  • 다른 사람의 테스트가 내 테스트에서 안 보이던 문제를 찾아 줍니다.
