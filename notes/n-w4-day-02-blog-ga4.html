오늘 한 줄 요약

내 블로그를 첫 화면 배포부터 관리자 로그인과 글쓰기까지 만들어 출시하고, 구글 애널리틱스(GA4)로 누가 어떤 글을 어떻게 읽는지 측정하는 이벤트를 설계했습니다.

오늘 진행 순서

단계목표내 결과
1차블로그 첫 화면 디자인 초안을 잡고 깃허브에 올려 배포첫 화면을 깃허브 페이지에 배포
2차아티팩트로 5개 화면 시안(첫 화면, 글 목록, 글 상세, 글쓰기, 관리자 로그인)을 만들고 공유 링크로 열기5개 화면 시안 완료
3차사용자 스토리 "관리자는 로그인 후에 글쓰기 기능으로 글을 직접 쓸 수 있다" 구현. 모르는 것과 해결 과정은 문서에 남기기구글 로그인, 글쓰기, 목록 반영까지 완료
추가(선택) 글마다 제목, 설명, 썸네일을 다르게 표시글마다 다른 썸네일과 링크 미리보기 적용
GA블로그에 GA를 설정해 방문자 수, 페이지별 방문자, 지역, 기기, OS, 가장 많이 읽힌 글 보기이벤트 설계와 코드 연결, 택소노미 문서 작성

요구사항과 CRUD로 본 블로그

  • 필수 요구사항: 로그인한 사람만 글을 쓸 수 있고, 글은 공개글과 나만 보기 글로 나뉩니다.
  • 주의 사항: API 키와 중요한 비밀값은 .env 파일에 저장합니다.

읽기(Read)글 목록, 글 상세(로그아웃이면 공개글만, 관리자는 모두)2차 화면, 3차 데이터

에이전틱 코딩 가이드: 문서 3종

AI와 함께 코드를 만들 때 문서 세 가지를 프로젝트에 두라는 안내가 있었습니다.

문서담는 것내 블로그에서
코드 개발 지침(시스템 프롬프트)디자인 규칙, 구조, 작업 방식인수인계 문서에 현재 상태, 디자인 규칙, 남은 일 정리
의사결정 문서무엇을 왜 그렇게 정했는지작업 기록의 "결정 사항"에 정리
실패 로그막힌 지점과 해결 과정(주제마다 따로)작업 기록에 증상, 원인, 해결, 확인할 것 순서로 번호를 붙여 기록

한도가 소진되기 직전에 작업 내용을 전부 깃허브에 올려 달라고 요청하고 코덱스로 옮겨 이어서 작업했는데, 이 문서들 덕분에 이어받기가 쉬웠습니다. 두 도구가 같은 저장소를 고치기 때문에 작업 전에 원격 최신을 먼저 확인했습니다.

블로그 설계: 정한 것들

결정이유
배포는 깃허브 페이지, 데이터와 로그인은 파이어베이스무료로 쓰고, 화면과 데이터를 나눠 관리
기존 파이어베이스 프로젝트 안에 이름 붙인 DB를 따로 만듦다른 저장소가 기본 DB에 규칙을 배포해서, 같은 DB를 쓰면 규칙이 덮어써질 수 있음
관리자는 구글 계정 한 개로 제한하고, 실제 차단은 DB 규칙에서화면에서만 막으면 우회될 수 있음
비밀값은 코드에 넣지 않고 설정 파일과 깃허브 변수에 보관키가 저장소에 올라가는 것을 막음
글 주소를 해시 방식에서 일반 주소로 변경글별 링크 미리보기를 만들기 위해
공개글과 나만보기 글, 카테고리를 DB로 관리필수 요구사항(로그인한 사람만 글쓰기, 공개 범위 구분)

GA4 이벤트 설계

알고 싶은 것부터 정하고, 그에 맞는 이벤트를 골랐습니다.

알고 싶은 것보는 이벤트구분하는 정보
홈 방문자 수화면 조회(page_view)화면 종류(홈, 전체 글, 글 상세)
가장 많이 읽힌 글화면 조회(page_view)글 번호, 글 제목, 카테고리
인기 카테고리카테고리 클릭(category_click)카테고리 이름, 클릭 위치
홈에서 어디를 눌러 글로 가는가글 선택(article_select)클릭 위치(카드, 목차, 다음 글 등)
끝까지 읽는 글글 스크롤(article_scroll)50%, 90% 지점
지역, 기기, OS, 유입, 이탈GA가 기본으로 수집코드 없이 확인
  • 블로그 방문자 수는 홈 화면 방문과 페이지별 조회로 셉니다.
  • 관리자 본인의 방문, 비공개 글, 임시저장 글, 글쓰기와 관리 화면은 집계에서 제외했습니다.
  • 점검할 점: 글 제목은 고치면 바뀌어서 이벤트에는 글 ID로 보내는 것이 안전하다는 안내가 있었습니다. 내 설계는 글 번호와 함께 글 제목도 보내므로, 제목을 계속 보낼지 정해야 합니다. 이름·이메일 같은 개인정보는 어떤 파라미터에도 넣지 않습니다.
  • 이벤트 설계 결과는 별도 문서(이벤트 택소노미)로 정리했습니다.

겪은 문제와 해결

증상원인해결
배포가 패키지 설치 단계에서 실패패키지를 추가하고 잠금 파일을 맞추지 않음잠금 파일을 다시 만들고 푸시 전에 로컬에서 같은 명령으로 확인
글 링크를 공유하면 기본 미리보기만 나옴미리보기 로봇은 자바스크립트를 실행하지 않고, # 뒤는 서버에 전달되지 않음글마다 정적 페이지를 만들고 일반 주소로 전환
붙여 받은 GTM 코드를 GA 측정 ID로 착각할 뻔함태그 매니저 ID와 GA4 측정 ID(G-)는 다른 값컨테이너에서 G- ID를 확인해 등록
로컬 미리보기가 실제 GA에 기록을 보낼 뻔함설정 파일에 실제 측정 ID가 있어서 켜짐테스트 빌드는 ID를 비워 실행
스크롤 이동이 계속 느림전역 부드러운 스크롤이 매 프레임 이동을 다시 늦춤프레임마다 즉시 이동으로 처리
보안 점검: 배포끼리 덮어쓸 수 있음, 목록 읽기 실패를 "변경 없음"으로 처리동시 실행 그룹이 나뉘어 있었고, 실패를 정상으로 취급함그룹을 합치고, 읽기 실패 시 실행도 실패로 종료

배운 점

  • 한 페이지짜리 앱은 화면이 바뀌어도 새로고침이 없어서 GA가 이동을 잡지 못합니다. 이동마다 화면 조회를 직접 보내야 합니다.
  • 이벤트에 붙인 정보(글 번호, 카테고리 등)는 맞춤 측정기준으로 등록해야 보고서에서 나눠 볼 수 있습니다. 등록하지 않으면 이벤트 개수만 보입니다.
  • 지역, 기기, OS, 유입, 이탈은 코드 없이 GA가 기본으로 모읍니다.
  • 측정 ID(G-)와 태그 매니저 ID(GTM-)는 다른 값이고, 둘을 같이 설치하면 같은 방문이 두 번 잡힙니다.
  • 링크 미리보기를 글별로 만들려면 해시 주소로는 안 되고 일반 주소가 필요합니다.
  • 확인하지 못한 것은 완료로 적지 않고 "확인 대기"로 표시합니다.

남은 일

  • GA 실시간 화면에서 이벤트가 들어오는지 확인하고 맞춤 측정기준 등록. 실시간 화면은 바로 보이지만 일반 보고서에는 24~48시간 뒤에 반영되고, 맞춤 측정기준도 등록 후 보고서에 보이기까지 24~48시간이 걸립니다.
  • 관리자 로그인 상태와 로그아웃 상태에서 같은 글을 열어, 로그아웃일 때만 이벤트가 들어오는지 확인
  • 카카오톡과 슬랙에서 링크 미리보기 확인
  • 이미지 업로드 기능 추가, 카테고리 관리와 로그인 화면 디자인 통일
