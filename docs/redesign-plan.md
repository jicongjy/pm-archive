# AI PM Archive 개편 계획서 (검토용)

상태: 초안. 코드는 아직 바꾸지 않았습니다. 검토 후 결정할 항목은 9장에 모았습니다.
주의: 이 저장소는 공개입니다. 이 파일은 커밋하지 않은 상태로 두고, 올리기 전에 지우거나 .gitignore에 넣습니다.

## 1. 목표

- 지금의 "결과물 전시 페이지"를 "학습 아카이브 대시보드"로 바꿉니다.
- 왼쪽 메뉴, 오른쪽 작업 영역, 둥근 카드 형태로 통일합니다.
- 결과물, 노트, 링크, 일정을 한 곳에서 찾고, 장기적으로는 사이트 안에서 쓰고 저장할 수 있게 합니다.
- 공개 방문자는 공개 항목만 보고, 비공개 내용은 저장소에 두지 않습니다.

## 3. 페르소나

1. 주 사용자: 홍지영, 멀티캠퍼스 AI PM 수강생. 매일 수업을 듣고 노트를 쓰고 실습물을 만든다. 하고 싶은 일은 (1) 어제 만든 결과물과 노트를 빨리 다시 열기, (2) 강사가 준 링크를 한곳에 모으기, (3) 이번 주에 무엇을 했는지 돌아보기, (4) 포트폴리오로 보여 주기다.
2. 방문자: 채용 담당자나 동료 수강생. 로그인 없이 들어와 30초 안에 "무엇을 만들었는지" 파악하고 싶다. 공개된 결과물과 노트만 본다.
3. AI 에이전트: 이 저장소의 AGENT.md를 따라 결과물과 노트를 갱신한다. 사람이 아니지만 사실상 사용자라서, 데이터는 사람이 열어도 읽히는 JSON과 마크다운 파일로 둔다.

### 4.3 더 필요한 메뉴 제안

- 회고: 별도 메뉴보다 "노트의 한 종류"로 두고 캘린더와 타임라인에서 모아 보는 쪽을 권합니다.
- 용어 및 PM 지식(knowledge): 수강 중 쌓이는 개념 정리. 중요하지만 2단계 후보입니다.
- 에이전트 패널: 오른쪽에 "이 사이트 내용으로 질문하기". 레퍼런스 5번처럼 매력적이지만 서버와 비용이 필요해서 후순위입니다.
- 수집함(Inbox): 로그인 후 단계에서 링크나 메모를 일단 던져 두는 곳. 레퍼런스 9번 참고.
- 빼는 것: 타임라인을 별도 메뉴로 두지 않고 캘린더의 보기 하나로 합칩니다. 결과물과 프로젝트도 하나로 합칩니다(9장 질문 2).

### 5.3 컴포넌트

- 데스크톱(1280 이상): 사이드바 248px + 본문 + 선택형 오른쪽 패널 320px

- 모바일(767 이하): 사이드바는 왼쪽 서랍, 하단에 탭 4개(홈, 프로젝트, 노트, 링크)
- 카드 갤러리: 열 수는 넓이에 따라 자동, 벽돌형은 CSS columns로 구현

- 색 대비 4.5:1 이상 확인(파스텔 면 위의 글자는 진한 색만 사용)
- 모션은 150~200ms, prefers-reduced-motion이면 끔

## 6. 사이트 안에서 글쓰기, 업로드, 링크 저장, 로그인

핵심 사실: GitHub Pages는 정적 호스팅이라 로그인해도 서버가 없습니다. 공개 저장소에 올린 것은 누구나 볼 수 있으므로, 비공개 노트를 "로그인으로 가리는" 방식은 안전하지 않습니다. 쓰고 저장하려면 저장 장소(백엔드)가 따로 필요합니다.

| 옵션 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 읽기 전용 유지 | 글은 지금처럼 클로드, 드라이브에서 쓰고 에이전트가 파일을 갱신 | 가장 단순하고 안전, 추가 비용 없음, 로그인 불필요 | 사이트에서 바로 쓰거나 링크를 저장할 수 없음 |
| B. Git 기반 편집 | 로그인한 본인만 브라우저에서 마크다운을 편집하고 저장소에 커밋(CMS 방식) | 비용 없음, 데이터가 파일로 남음 | 모든 글이 저장소에 들어가서 공개 저장소에는 비공개 글을 둘 수 없음. 사용 방법이 다소 번거로움 |
| C. 백엔드 추가(Supabase 등) | 로그인, 데이터베이스, 파일 저장소를 붙임. 글마다 공개 여부 표시, 규칙으로 본인만 비공개 글 열람 | 쓰기, 업로드, 링크 저장, 비공개 노트가 모두 가능. 무료 구간 충분 | 구성 요소가 늘고 관리할 것이 생김. 링크 미리보기는 서버 함수가 추가로 필요 |

권장: 단계별로 갑니다.
- 1단계는 옵션 A로 새 디자인과 메뉴를 먼저 완성합니다. 링크 모음과 캘린더는 JSON 파일로 채웁니다.
- 2단계에서 정말 필요해지면 옵션 C를 붙입니다. 그때 추가할 것은 다음과 같습니다.
  1. 로그인: 본인 한 명만 허용(이메일 링크 또는 깃허브 로그인), 방문자는 로그인 없음
  2. 데이터베이스: 노트, 링크, 일정, 설정. 항목마다 "공개" 표시
  3. 파일 저장소: 업로드한 파일. 공개와 비공개 구분
  4. 마크다운 에디터: 처음에는 입력창과 미리보기, 이후 서식 편집기
  5. 링크 저장: 주소를 붙여 넣으면 제목과 대표 이미지를 가져오는 서버 함수
  6. 공개 전 점검: 이메일, 전화번호, 키 패턴 경고
  7. 백업: 주기적으로 JSON을 비공개 저장소에 내보내기

## 7. 데이터 구조 (1단계)

- data/works.json: 지금 구조에 project, related(노트와 링크 id) 필드 추가
- data/notes.json과 notes/*.md: 공개 표시된 노트만 변환해서 넣음. 변환은 tools/export_notes.py가 하고, 교안 상세, 슬랙 내용, 개인 회고, 작성자 메모는 제거
- data/links.json: id, 제목, 주소, 출처(강사, 실습, 읽을거리), 태그, 날짜, 메모
- data/events.json: 일정(수업, 제출, 회고)
- 화면 이동은 해시 경로(#/projects, #/notes/아이디)로 하고 빌드 없이 유지

## 9. 결정이 필요한 것

1. 쓰기와 로그인: 지금은 읽기 전용(A)으로 시작하고 나중에 C를 붙이는 안에 동의하는지
2. 프로젝트와 결과물: 하나로 합치는 안(권장)인지, "프로젝트 안에 여러 결과물"로 나눌지
3. 색: 인디고 강조와 주차별 파스텔로 진행해도 되는지(레퍼런스 1, 17번과 비슷한 방향)
4. 이름 노출: 사이드바 프로필에 이름(홍지영)과 한 줄 소개를 공개해도 되는지
5. 에이전트 패널과 지식 메뉴: 이번 범위에서 빼도 되는지
