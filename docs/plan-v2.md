# 학습 보관함 기획 v2 (초안)

> 이 문서는 로컬 전용입니다. 커밋하지 않습니다. 인터뷰 답변을 바탕으로 정리한 초안이고, 확정 전입니다.

## 1. 한 줄 정의

과정이 끝날 때까지 매일 쌓이는, 나를 위한 공개 학습 보관함. 지난주에 무엇을 했는지 돌아보고, 만든 것을 다시 열고, 어디서 배웠는지 찾고, 얼마나 컸는지 확인한다.

## 2. 인터뷰에서 확정된 것

| 질문 | 답 |
|---|---|
| 첫 번째 사용자 | 나 자신 (학습 기록) |
| 첫 번째 행동 | 전체 기록을 훑어보기 |
| 자주 할 일 | 그 주에 뭘 했는지 돌아보기 / 예전에 만든 결과물 다시 열기 / 이 개념을 어디서 배웠는지 찾기 / 내가 얼마나 성장했는지 보기 |
| 범위 | 학습 보관함 전체 (결과물, 노트, 교안, 링크, 용어) |
| 수명 | 과정이 끝날 때까지 계속 쌓기 |
| 공개 | 전부 공개 (저작권과 개인정보는 걸러서) |
| 첫 화면 | 깃허브 잔디처럼 뿌듯하게 확인되는 것 / 주차별 타임라인 / 최근 추가 / 배운 것 요약, 용어 |
| 지금 사이트의 문제 | 무엇을 위한 사이트인지 모르겠다 / 메뉴와 기능이 많은데 쓸모가 없다 / 보여 주고 싶은 것이 묻힌다 / 디자인이 마음에 안 든다 |

## 3. 문제 진단

기획 없이 만들었기 때문에 생긴 문제를 인터뷰 답변에 맞춰 보면 다음과 같다.

1. 목적이 흐리다. 포트폴리오처럼 시작했는데, 실제로 필요한 것은 "나를 위한 학습 기록"이다. 방문자를 설득하는 화면(대표 카드, 큰 숫자)은 필요 없다.
2. 기능을 먼저 붙였다. 캘린더, 링크 모음, 차트가 "자주 할 일" 네 가지와 연결되지 않는다.
3. 같은 정보가 흩어져 있다. 그 주에 한 일이 프로젝트, 노트, 교안, 캘린더에 따로 있다.
4. "어디서 배웠는지 찾기"와 "성장 보기"는 지금 사이트에 거의 없다.

## 4. 사용자 시나리오 (자주 할 일 4가지)

| # | 하고 싶은 일 | 지금 | 필요한 것 |
|---|---|---|---|
| A | 그 주에 뭘 했는지 돌아본다 | 프로젝트, 노트, 교안이 따로 있음 | 주차 한 화면에 결과물, 노트, 교안, 배운 용어가 모인다 |
| B | 예전 결과물을 다시 연다 | 프로젝트 목록 | 결과물 목록 + 검색. 바로 열기 |
| C | 이 개념을 어디서 배웠는지 찾는다 | 용어 9개가 직접 쓴 정의라서 노트와 연결이 없음 | 용어 → 나온 노트, 교안, 결과물로 역링크 |
| D | 얼마나 성장했는지 본다 | 없음 | 잔디(활동량), 주차별 변화 요약 |

## 5. 정보 구조 초안

메뉴를 "자주 할 일" 기준으로 줄인다.

- 홈: 잔디, 주차별 타임라인, 최근 추가, 배운 것 요약
- 주차: 주차별 돌아보기 화면 (A, D)
- 결과물: 목록과 열기 (B)
- 노트: 내가 쓴 공개 노트 (읽기)
- 용어: 용어 → 배운 곳 (C)
- 자료: 교안 링크, 강사 예시 링크

지금의 7개(홈, 프로젝트, 노트, 링크, 교안, 캘린더, 용어)에서 캘린더를 없애고(잔디와 주차가 대신함), 링크와 교안을 자료로 합쳐 6개로 줄이는 안이다. 합치는 것은 결정이 필요하다.

## 6. 홈 화면 구성 (초안)

1. 잔디: 날짜별 활동량. 활동은 결과물, 노트, 용어 추가로 센다.
2. 주차별 타임라인: 1, 2, 3주차를 한 줄로, 각 주에 한 일 수.
3. 최근 추가: 최근 결과물과 노트 몇 개.
4. 배운 것: 최근 용어와 한 줄 정의.

## 7. 결정이 필요한 것

1. (확정) 성장은 잔디(활동량)와 주차별로 만든 것의 수와 종류, 두 가지로 보여 준다. 직접 쓰는 주간 회고는 넣지 않는다.
2. (확정) 잔디 한 칸은 하루의 결과물 + 노트 + 용어 추가 건수를 합쳐서 센다.
3. (확정) 노트에 `용어: PRD, MVP` 같은 줄을 달아 두면 내보내기 도구가 자동으로 모은다. 용어 정의는 내가 노트에 쓴 문장을 쓴다(저작권 부담 적음). 지금 직접 쓴 9개 정의는 이 방식으로 대체한다.
4. (확정) 교안은 해당 주차 화면 안에 넣고, 링크 모음(강사 예시)만 별도 메뉴로 남긴다. 메뉴는 홈, 주차, 결과물, 노트, 용어, 링크 모음 6개가 된다. 교안 메뉴와 캘린더 메뉴는 없앤다.
5. (확정) 디자인 방향은 아래 9번에 정리한다.

## 8. 하지 않을 것 (이번 범위 밖)

- 사이트 안에서 글 쓰기, 업로드, 로그인 (읽기 전용 유지)
- AI 질문 패널
- 방문자 설득용 대표작 연출

## 9. 디자인 방향 (확정된 것과 아직 안 정한 것)

### 마음에 든 레퍼런스
Mantra 프로젝트, Amplifidor와 Memo의 벽돌 카드, 학생 대시보드와 Duxica, Skylar 블로그와 저널 앱. 이 네 갈래를 모두 고르셨으므로, 한 화면에 모두 섞지 않고 화면별로 나눠 쓴다.

| 화면 | 따를 레퍼런스 |
|---|---|
| 사이드바, 전체 틀 | Mantra, Skylar (프로필, 섹션 제목, 외부 링크 화살표) |
| 홈 | 학생 대시보드, Duxica (인사말, 진행 카드, 오른쪽 패널) |
| 결과물, 링크 | Amplifidor, Memo (크기와 종류가 다른 벽돌 카드) |
| 노트 읽기 | 저널 앱 (제목에 명조체, 넉넉한 여백) |

### 지금 디자인이 별로인 이유 (본인 진단)
1. AI가 만든 디자인의 특징이 너무 많다. 지나치게 작은 글자, 넓은 자간, 프리텐다드가 아닌 영문 글꼴.
2. 카드 구조가 전부 비슷하다.
3. 카드에 불필요한 정보가 AI 특유의 방식으로 들어 있다. 어떤 정보를 어디에 보여 줄지 정보 구성부터 다시 기획해야 한다.
4. 너무 회색이고 밋밋하다.
5. 레퍼런스만큼 고급스럽지 않다.
6. 정보를 찾기 어렵다.

### 여기서 나오는 원칙 (초안)
- 글꼴은 프리텐다드 하나로 통일한다. 영문과 숫자도 프리텐다드. 본문은 14px 이상으로 키우고, 자간은 기본값으로 둔다.
- 카드에는 "자주 할 일" 네 가지에 답하는 정보만 넣는다. 파일 크기, 막대 그래프 같은 장식성 정보는 뺀다.
- 카드 종류는 정보가 다르기 때문에 다르게 만든다. 모양만 바꾼 변주는 하지 않는다.
- 색은 회색 일색에서 벗어난다. 어떤 색을 쓸지는 아직 정하지 않았다.

### 아직 안 정한 것
- 색: 무채색 기반에 포인트 색을 하나 쓸지, 주차별로 색을 둘지.
- 카드별로 보여 줄 정보 목록 (다음 단계에서 정한다).

## 10. 카드 정보 설계 (초안)

원칙: 카드의 모든 정보는 "자주 할 일" 네 가지(A 주차 돌아보기, B 결과물 열기, C 어디서 배웠나, D 성장) 중 하나에 답해야 한다. 어느 쪽에도 답하지 못하면 뺀다.

### 10-1. 지금 카드에서 빼는 것
| 정보 | 이유 |
|---|---|
| 파일 종류와 크기 (웹 문서 · 3.2MB) | 어느 일에도 답하지 못한다 |
| 같은 날 학습 노트 N개 | 날짜가 같을 뿐 관련이 없을 수 있다 |
| 노트의 읽기 시간, 구성 막대 | 노트를 고르는 데 도움이 안 된다 |
| 링크 라벨 줄 | 상세 화면에서 보면 된다 |
| 수업일 막대 (이미 뺌) | 설명 없이 읽히지 않는다 |

### 10-2. 카드별 정보

| 카드 | 답하는 일 | 보여 줄 정보 | 클릭하면 |
|---|---|---|---|
| 결과물 | B, C | 화면 이미지, 제목, 한 줄 설명, 만든 날과 주차, 이 결과물에 쓴 용어 | 결과물 열기 (상세에서 노트와 연결) |
| 노트 | A, C | 날짜와 주차, 정리된 제목, 이날 내가 한 것 한 줄, 이날 배운 용어 | 노트 읽기 |
| 용어 | C | 용어, 한 줄 정의(내 문장), 처음 나온 날, 나온 곳 N곳 | 나온 노트와 결과물 목록 |
| 주차 | A, D | 주차와 기간, 만든 결과물 수, 노트 수, 배운 용어 수, 대표 결과물 이미지 몇 장, 교안 링크 | 그 주 화면 |
| 링크 | (자료) | 제목, 주소, 왜 좋은지 한 줄 메모 | 새 창에서 열기 |

### 10-3. 카드가 서로 달라야 하는 이유
카드의 모양이 아니라 보여 주는 정보가 다르기 때문에 서로 다르게 보이게 한다.
- 결과물: 이미지가 주인공.
- 노트: 글(한 줄과 용어)이 주인공.
- 용어: 정의가 주인공. 이미지 없음.
- 주차: 숫자와 이미지 묶음이 주인공.
- 링크: 주소와 메모가 주인공. 가장 작다.

### 10-4. 필요한 데이터 (지금 없는 것)
- 결과물의 한 줄 설명: 지금 12개 중 일부만 있고, 일부는 제가 임의로 쓴 문장이다. 직접 쓴 문장으로 바꿔야 한다.
- 결과물 ↔ 노트 연결: 지금은 날짜가 같으면 묶는다. 정확하게 하려면 연결을 명시해야 한다.
- 노트의 "이날 내가 한 것" 한 줄: 지금은 본문 첫 문장을 자동으로 가져와서 부정확하다.
- 용어 ↔ 노트 연결: 3번 결정대로 노트에 `용어:` 줄을 단다. 아직 하나도 달려 있지 않다.
- 링크의 메모: 아직 없다.

### 10-5. 카드 정보 결정 (확정)
6. 결과물의 한 줄 설명은 "무엇을 했는지"를 쓴다. 예: "신청서 위치를 바꾼 안의 신청 완료율을 비교하는 A/B 테스트 계획서".
7. 결과물과 노트의 연결은 노트에 명시한다. 노트에 `결과물: 아이디` 줄을 달고, 내보내기 도구가 읽는다. 날짜가 같다는 이유로 묶는 방식은 쓰지 않는다. (용어 표시와 같은 방식)
8. 링크 카드의 "왜 좋은지" 메모는 선택 항목이다. 적은 링크에만 보이고, 비어 있으면 카드에 자리를 차지하지 않는다. (답이 "선택"이라 이렇게 해석함. 다르면 수정)
9. 한 줄 설명과 메모는 제가 초안을 쓰고 사용자가 고친다. 사이트에 올리기 전에 목록으로 전부 보여 주고 승인받는다.

## 11. 화면별 구성 (초안)

### 11-0. 공통 틀
```
┌ 사이드바 ──────┬ 본문 ─────────────────────────────┐
│ 프로필(이름,    │ 검색창                    오늘 날짜 │
│  한 줄 소개)    │ ───────────────────────────────── │
│ 홈             │                                   │
│ 주차           │          화면별 내용               │
│ 결과물   12    │                                   │
│ 노트     8     │                                   │
│ 용어     N     │                                   │
│ 링크 모음 5    │                                   │
│ ─────────      │                                   │
│ 깃허브 ↗       │                                   │
└────────────────┴───────────────────────────────────┘
```
메뉴 순서는 "자주 할 일" 순서(돌아보기, 열기, 찾기)를 따른다. 확정: 사이드바의 "최근 항목"과 "주차" 목록은 뺀다. 메뉴 6개와 깃허브 링크만 둔다.

### 11-1. 홈 (A, D: 전체를 훑고 뿌듯함을 확인)
```
안녕하세요, ○○님            (한 줄: 오늘로 N일째, 결과물 N개)
┌ 잔디 ──────────────────────────────────────┐
│ 수업 기간 전체 날짜별 칸. 칸 색 = 그날 결과물+노트+용어 건수 │
└────────────────────────────────────────────┘
┌ 주차별 변화 ───────────────┐ ┌ 최근 추가 ───────┐
│ 1주  결과물 2 노트 0 용어 0 │ │ 결과물/노트/용어 │
│ 2주  결과물 2 노트 4 용어 N │ │ 시간순 5개 목록   │
│ 3주  결과물 8 노트 4 용어 N │ └──────────────────┘
│ (막대 + 종류별 색)          │ ┌ 최근 배운 용어 ──┐
└─────────────────────────────┘ │ 용어 + 한 줄 정의 │
                                └──────────────────┘
```
빼는 것: 대표 카드, 달력, 링크 패널, 큰 숫자 통계 카드.

### 11-2. 주차 (A: 그 주에 뭘 했는지) — 확정: 3주를 한 페이지에 세로로
주차 메뉴를 누르면 1, 2, 3주차가 위에서 아래로 이어진다. 주차가 늘어나면 위쪽에 주차 점프 링크를 둔다. 한 주를 한 덩어리로 본다. 위에서 아래로: 그 주의 숫자 → 만든 결과물 → 쓴 노트 → 배운 용어 → 교안 링크.
```
2주차  11.02 ~ 11.06       결과물 2  노트 4  용어 N
[ 결과물 카드 ][ 결과물 카드 ]
노트   11.02 ... / 11.03 ... / 11.04 ... / 11.05 ...
용어   PRD · MVP · ...
교안   DAY3 ↗  DAY4 ↗
```

### 11-3. 결과물 (B: 예전 것 다시 열기)
상단에 주차와 종류 필터, 그 아래 벽돌 카드. 카드를 누르면 상세(왼쪽 정보, 오른쪽 결과물 화면).
상세 왼쪽: 제목, 한 줄 설명, 열기 버튼, 만든 날, 쓴 용어, 이 결과물을 다룬 노트(명시한 것만), 이전·다음.

### 11-4. 노트 (A, C) — 확정: 왼쪽 목록 + 오른쪽 읽기 (저널 앱)
왼쪽에 날짜순 노트 목록, 오른쪽에 읽기 화면. 읽기 화면 위쪽에 이날 배운 용어와 연결된 결과물(명시한 것만)을 둔다. 모바일에서는 목록 → 읽기 두 화면으로 나눈다.

### 11-5. 용어 (C: 어디서 배웠나)
가나다순 목록. 용어를 누르면 정의와 "나온 곳"(노트, 결과물)이 나온다. 목록 위에 용어 검색.

### 11-6. 링크 모음
작은 카드 목록. 제목, 주소, 메모(선택). 분류 없음.

### 11-7. 검색
상단 검색창은 결과물, 노트, 용어, 링크를 한 번에 찾는다. 결과는 종류별로 묶어서 보여 준다.

## 12. 색과 글꼴

### 확정
- 글꼴: 프리텐다드 하나. 영문과 숫자도 프리텐다드. 명조체는 쓰지 않는다. 시스템 글꼴(SF 등)을 앞에 두지 않는다.
- 글자 크기: 본문 16px, 보조 14px, 최소 13px. 12px 이하는 쓰지 않는다. 자간은 기본값.
- 색 방향: 노션이나 Arc 같은 깔끔한 대시보드 톤. 레퍼런스 사진들과 같은 톤. (제안한 세 팔레트 A, B, C는 모두 채택하지 않았다)

### 색 (확정: "지금 좋다", 단 아래 수정 반영)
인디고 안은 폐기. 모노톤을 기본으로 하고 빨간색을 정말 일부에만 쓴다.
- 바탕 #F7F7F7, 카드는 흰색에 1px 옅은 테두리(#E6E6E6), 사이드바 #F0F0F0, 글자 #1F1F1F, 보조 글자 #777.
- 태그(종류, 주차)는 전부 회색. 색으로 구분하지 않고 글자로 구분한다.
- 잔디는 회색 단계(옅음에서 검정). 
- 빨강(#E03A2F)은 딱 두 곳: (1) 잔디의 오늘 칸, (2) 새로 추가된 항목 앞의 작은 점.
- 선택한 메뉴는 레퍼런스처럼 채운 알약(Mantra, Skylar, Arc)으로 표시한다. 왼쪽 막대(라인)는 쓰지 않는다.
- 카드 모서리 8px, 그림자 없음.

### 금지: AI 디자인 특징 (레퍼런스에 충실할 것)
- 카드나 메뉴 왼쪽의 색 막대, 한쪽만 있는 굵은 테두리.
- 의미 없는 장식선, 그라데이션, 글로우.
- 레퍼런스에 없는 요소는 새로 만들지 않는다. 새 요소가 필요하면 레퍼런스에서 같은 역할을 하는 것을 찾아 그대로 따른다. (선택 표시는 알약, 태그는 옅은 알약, 카드는 흰 면에 옅은 테두리)

## 13. 데이터 준비 순서

### 13-1. 노트에 다는 표시 형식 (노트 앞쪽 12줄 안)
```
공개: 예
결과물: w3-reading-menu, w3-book-proto
용어: PRD | 제품이 무엇을 해야 하는지 적은 문서
용어: MVP | 가장 작게 만들어 먼저 검증하는 버전
한줄: 독서 메뉴 개발본을 고치고 UX 점검 슬라이드를 만들었다
```
- 이 줄들은 내보낼 때 본문에서 지워진다(지금 `공개: 예` 줄과 같은 방식).
- 용어는 노트마다 여러 줄. `용어: 이름 | 정의` 형식. 정의는 내 문장.
- 결과물 아이디는 `data/works.json`의 id. 목록은 도구가 알려 준다.
- 한줄은 노트 카드의 "이날 한 것"에 쓴다.
- 줄이 없는 노트도 내보내진다(카드에서 해당 칸만 비어 있음). 막지 않는다.

### 13-2. 단계

| 순서 | 할 일 | 누가 | 결과 |
|---|---|---|---|
| 1 | 표시 형식 확정(위 13-1) | 같이 | 형식 확정 |
| 2 | 노트 템플릿에 세 줄(결과물, 용어, 한줄) 추가. 앞으로 쓰는 노트는 처음부터 달고 시작 | 제가 제안, 사용자 승인 | 새 노트에 자동 적용 |
| 3 | 기존 노트 8개의 초안 목록 만들기: 노트별로 결과물 연결 후보, 용어 후보와 정의, 한줄 | 제가 초안 | 목록 1장 |
| 4 | 결과물 12개의 한 줄 설명 초안 목록 만들기("무엇을 했는지") | 제가 초안 | 목록 1장 |
| 5 | 링크 5개의 메모 (선택, 적고 싶은 것만) | 사용자 | 있는 것만 |
| 6 | 3, 4, 5번 목록을 보고 사용자가 고친다 | 사용자 | 확정본 |
| 7 | 확정본을 비공개 노트 저장소에 반영 (노트 8개에 줄 추가, 커밋) | 제가, 승인 후 | 노트 저장소 갱신 |
| 8 | 내보내기 도구 수정: 세 가지 줄을 읽어 `notes.json`, `terms.json`, 결과물 연결 데이터를 만든다. 빠진 것을 보고서로 보여 준다 | 제가 | 도구 |
| 9 | 도구로 내보내고 결과 확인 | 제가 | 사이트 데이터 |
| 10 | 새 화면 만들기 시작 | 제가 | 사이트 |

초안과 확인(3~6)이 끝나기 전에는 사이트 코드를 바꾸지 않는다.

### 13-3. 사이트가 쓰는 데이터 (최종)
- `notes.json`: 노트 + 한줄 + 연결된 결과물 + 용어 목록
- `terms.json`: 노트에서 모은 용어(이름, 정의, 처음 나온 날, 나온 노트와 결과물). 지금 직접 쓴 9개 정의는 폐기
- `works.json`: 결과물 + 한 줄 설명 (제가 임의로 쓴 큰 숫자 `metric`은 폐기)
- `links.json`: 링크 + 메모(선택)
- 잔디와 주차별 변화는 데이터에서 계산한다. 따로 입력하지 않는다.
  - 하루의 칸 = 그날 만든 결과물 + 그날 쓴 노트 + 그날 처음 나온 용어
  - 용어의 날짜 = 그 용어가 처음 달린 노트의 날짜

### 13-4. 위험과 확인할 것
- 용어 정의를 "내 문장"으로 쓰므로 교안 문장을 그대로 베끼지 않는다. 초안에서 교안 문장처럼 보이는 것은 다시 쓴다.
- 1주차에는 노트가 없다(노트 저장소의 1주차 노트는 공개 표시가 없다). 1주차 잔디는 결과물만으로 칠해진다.
- 결과물 아이디가 바뀌면 연결이 끊어지므로, 도구가 연결된 아이디가 없을 때 경고한다.
